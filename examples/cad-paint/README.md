# CAD painting spool

The CAD shuttle emits a revision-bound request with intent, part identities, geometry, appearance observations and operator direction. It owns no model or renderer. The web CAD host owns the lock. The source package includes the domain agent policy and a provider-independent TypeScript planner. The model endpoint and credentials belong to its caller.

The domain agent proposes the materials missing from the saved request. The studio turns only validated string and number literals into the function in a fresh kit copy. With complete CAD materials the baseline runs directly. The native delivery contains Python silk and kit. It needs no model connection during rendering. The resulting ORA embeds the resolved scene, input digest and selected kit digest. Opening Krita and handing an accepted asset to a cutter are separate operations in the host.

Use Loom dev-advance to check this directory, pack the selected sources, verify the printed archive, and export it with export-native-spool-v3. Load that delivery with an operator-bound Python environment matching native-spool.toml. If the request needs a material proposal, install the reviewed kit in the instance before starting the attempt. Its input slot is request.json. Run the acceptance command only in a separately selected environment with the rendering dependencies.

The browser studio uses this same silk entry through a local development runner. Its successful render does not create an an-agent-host artifact acceptance. Loom's produces declaration supports future routing of a host-accepted artifact. A receiving cutting spool and a subscription must be separately configured in a managed host.
