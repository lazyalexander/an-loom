# an-loom 贡献者契约

[English](../../AGENTS.md) · 中文译文，以英文为准。 · [中文目录](README.md)

这是单个仓库的指令入口点。它提供开发指导，而非运行时授权。在提出新契约之前，应阅读[架构](docs/architecture.md)以及相关实现。

## 产品与所有权

Loom 帮助开发者将领域知识和现有软件转化为可复用的 spool 发布。它搭建、准备受限的编码任务、请求检查、验证证据并打包选定的字节。重用成熟编码工具和工作流程引擎；不实现竞争的编辑或模型循环。

- **Silk** 标签每个选定发布中的不可变文件，包括程序、配置、技能和代理指令。开发变更创建一个新的发布。
- **Kit** 标签授权的可变工作副本和新生成的工作，无论用途或目录如何。指令保持保护；修改一个程序或配置不会修改其发布基线或授予执行。未保留的 kit 只有在确认收尾完成后才能被回收。接受的产品和已提交的状态有独立的保管权。见[内容契约](docs/spool-code.md)。
- 一个 **workflow** 描述一个领域过程，结合 silk、代理和人类决策。这是术语，而不是新的运行时或模式。
- 一个 **spool release** 承载领域实现、silk、指令、配置、状态模式、迁移和接受规则。一个 spool 执行尝试是隔离和生命周期单元，与已提交状态不同。
- **an-agent** 拥有运行时权限，模型/上下文服务、执行监督、已提交状态、已验收的产物、保留和边界证据。
- 一个 **backend** 强制隔离并确认执行终止。一个 **shuttle** 介于授权交互与外部应用程序之间。

保持领域决策在 spool 项目中，宿主实现远离 Loom 和运行时依赖，an-agent 不得依赖 Loom。使用 Rust 2024 和 FP 风格：确定性规划/验证在中心，显式效果适配器在边缘。负载语言是开放的。

见[spool 边界和命名兼容性](docs/spool-boundary.md)。现有 `kit` CLI/配置/API 令牌和历史 Silk 通信记录保持兼容性身份；永不全局替换它们或重写旧发布。OpenShell 属于宿主后端适配器后，不在 Loom 或语义逻辑中。

## 变更与审核

- 代码注释和示例代码保持英文。英文文档是权威的。简体中文文档是配套译文。
- `main` 是稳定的；其推广仍需维护者审核并合并。`dev-advance` 是开发权威。从它进行普通工作，以及目标特征的PR。代理可在差分审查后合并开发PR，适用本地/真实接受和所有所需CI检查通过在选定的头部完成。
- 如果更改可能暴露私有数据、凭证、转录或材料，且其发布范围不明确，需暂停用户审核。禁止强制推送、绕过保护或削弱门禁。仓库指导不能创建运行时权限或覆盖隐私限制。
- 每次开发合并后，需通知用户，包括仓库、PR、目标分支、结果提交和简短描述。开发授权不包含主。
- 保持PR范围稳定；仅在移交后添加修复或审核回应。独立跟进从开发开始。依赖工作可继续在本地分支上进行，其基础PR/提交记录，然后使用已验证的合并开发前发布。不要创建长隐藏的集成链。
- 将主分支推广作为单独的PR由维护者处理；不得自动合并。在使用作为其他任务基础之前，需在合并后验证远程开发祖先。
- 仅在本地分支超过7天且已合并到开发且未在任何工作区中检出时清理本地分支。保留main/dev-advance和未合并的工作，验证祖先并使用安全删除。不要将工作区分离以使其分支符合资格。
- 区分已实现的保证、工具声明和提议的能力。除非任务明确改变，否则保留原有行为。
- 通用打包比受控执行支持更广泛。打包的遗留部署适配器仍为一个无依赖的Rust源码和`file-kit-v1`。独立的原生 spool 适配器导出有明确边界的 silk 发布和显式v3 Python/二进制请求，使用操作者选择的环境；其宿主契约和真实接受已在`docs/native-spool.md`中文档化。
- 使用宿主工作区配置的示例不增加spool ABI。
- 保留包括允许列表、路径包含、秘密检查、确定性身份、独占目的地和归档验证。
- 保留上游许可证和锁定的来源。保留历史的an-waver材料直到其剩余使用引用被检查。
- 仓库钩子、插件、MCP服务器、代理覆盖和构建脚本作为审查输入。指令和钩子不能扩展宿主权限。不要隐式执行项目命令、禁用隔离或启用宽泛批准，以使接受看起来成功。显示精确命令、选定输入、输出边界和批准要求；披露不支持的控制。
- 外部代理拥有其上下文和原生磁带。不要爬取私有会话存储或要求转录摄入。宿主保留尝试身份、有效权限、终止证据和接受输出参考。直接模型API追踪是独立的、可选的集成选择，其缺失使用和未知结果已披露。见[编码工具契约](docs/code-agents.md)。

## 已有的代理和工作流程工具

准备受限任务，包含相关输入引用、可编辑路径、可复用的kit入口点、接受命令和预期输出。优先调用现有silk，而不是让代理重新创建它。保留供应商特定行为在限定适配器中；不要从另一个CLI的标志中推断支持。

仓库钩子、插件、MCP服务器、代理覆盖和构建脚本作为审查输入。指令和钩子不能扩展宿主权限。不要隐式执行项目命令、禁用隔离或启用宽泛批准，以使接受看起来成功。显示精确命令、选定输入、输出边界和批准要求；披露不支持的控制。

## 证据和公共卫生

保留凭证、机器配置、绝对用户路径、原生转录和隐私记录不出公共文件。发布可移植摘要与本地操作数据分开。不声称哈希认证发布者、文件系统备份逆转外部影响或进程退出证明远程或分离工作已停止。未知结果需 reconciliation，而非自动重试。

在提交之前：

- `cargo fmt --all -- --check`
- `cargo test --locked`
- `cargo clippy --all-targets --locked -- -D warnings`
- `cargo quality --base TARGET` — 使用 `origin/dev-advance` 用于开发 PR，使用 `origin/main` 用于稳定推广，匹配实际 PR 目标。
- `cargo test --manifest-path tools/quality/Cargo.toml --locked`

TOML 质量政策和空基准是合并门，而非沙盒许可。不提高限制或添加例外以使功能通过。参见 [质量规则](docs/quality.md)。

真实宿主接受度在声称新执行保证之前是必需的。Fixture 单独不足以满足要求。遵循 [路线图](docs/roadmap.md)：在更改身份前研究发布线性，于成长文件管理前观察真实工作流，并在添加目录前验证一个编码工具适配器。在 PR 中报告变更、实际验证和剩余限制。

## 测试放置

遵循 [测试地图](tests/README.md)。私有单元测试位于相邻 `tests.rs`/`tests/` 模块后边 `cfg(test)`；公共契约测试位于 `tests/` 下，有聚焦的本地支持。在移动文件时保留 Cargo 目标名称、断言和忽略真实宿主覆盖率。领域测试保持与示例一致；质量工具测试保持在各自的独立工作区。生成输出和私有接受数据永不成为源固定。

## 平台声明

维护 [平台矩阵](docs/platforms.md) 中的工具/手递覆盖和链接到代理的权威运行时矩阵。保留 OS 特定宿主合同在适配器中，接受前提在测试入口点。现有 profile ID、历史证据和不支持平台的拒绝保持兼容。不添加运行时依赖、回退或较弱门以使目标通过。

## 测试语言与宿主协调

遵循 [测试地图和执行规则](tests/README.md)。保留 Rust 用于内部不变量和私有故障缝；偏好 Python 用于新黑盒 CLI 接受，以及 TS 当浏览器集成需要时。不将成熟套件仅为统一语言或为外部测试添加生产调试 API。

Loom 拥有开发/包/证据合同；an-agent 拥有执行、终止和保管执行。保持配对接受狭窄，并记录两者修订和二进制身份。一次构建每个选定修订和目标/配置，然后显式指定二进制路径给外部运行器。

上述检查仍为必需。运行受影响的 Python/TS 和真实宿主套件分开：Cargo 成功单独不意味着完整接受。在迁移期间保留覆盖率、故障案例和门，测量构建与执行，并且永不自动重试未知执行结果。
