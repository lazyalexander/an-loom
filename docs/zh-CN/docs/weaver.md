# Weaver：审查领域知识以进行spool开发

[English](../../weaver.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

Weaver是一个可选的任务准备和候选代码审查角色。使用现有的原生框架直接进行操作；Loom不会启动第二个代理循环，不拥有自己的对话，也不维护特定提供者的生成监督者。领域源选择、规则和测试属于项目，而不是框架。

第一个示例使用公开日志材料：选择精确的源，起草一个DOMAIN.md文件，包含源引用和未解决的问题，审查其精确字节和受保护的验收脚本，然后将一个有界的工具包分配提交给一个成熟的编码CLI。一个源、规范或验收变更将使审查失效。候选代码不能重新定义这些文件。审查意味着对需求的同意，而不是执行或披露无关私有源的许可。

保留所选源摘要、起草/审查身份、候选身份和检查结果。哈希绑定字节；它们不认证审查者或证明领域规则的真实性。本地权威文件必须保持操作者所有。一个外部编码工具保留自己的上下文和磁带。一个私有源不因包含在包中的派生规则而发布。

## 独立和受管理的操作

一个spool可以提供一个独立的CLI用于开发，而无需安装或挂载代理。这种零挂载模式支持本地领域测试和普通的Loom检查/打包/验证。它以操作者的原生权限运行；它不提供宿主隔离、结算、授权或正式的产物保管。独立的结果不得被伪造为接收检查/打包任务宿主证据。

由我们平台管理的正式操作需要代理准入、选定的发布/实例身份、明确的执行授权和宿主结算及产物接受。仅加载并不等于激活或执行批准。独立迭代不会改变这些要求。这是一个平台合同，而不是声称公共可执行文件不能在其他地方运行。

## 所有权

- Weaver：提出来源需求和测试；揭示冲突；根据批准的规则审查代码。它不能批准自己的权限。
- L
- Loom：版本开发材料，保护基线，接收候选代码，组织检查并打包精确选定的字节。离线打包仍然可用，且不涉及受控执行的声明。
- an-agent：授权访问/披露和执行，监督尝试并拥有接受的状态/产品。它不解释领域规则。
- 开发者：解决领域模糊性，确认规范，并决定发布/权限变更。编码工具实现范围内的分配。

一个供应商钩子是一个可选的入口点，而不是强制性的全局提示拦截器或安全边界。模型输出和检索到的文档仍然是不可信的输入。优先选择显式的源选择和经过审查的任务，而不是模糊的提示重写。现有的有界上下文API不提供通用的知识库权限服务。宿主工具包建议插槽不是Weaver。

第一个实现是一个带有文件合同的示例适配器，而不是通用的Weaver运行时或多文件编码代理沙盒。不同的框架可以在保留审查输入和候选输出的同时替换适配器。

## Loom层和可选策略

Loom的责任是合同、验证和交付：绑定开发输入和候选代码，收集静态发现以及项目拥有的验收或压力证据，并打包精确选定的字节。领域案例由项目提供；通用压力测试不能建立领域正确性。

Weaver 属于一个可选的面向 Loom 的模块，具有可替换的 harness 适配器，而不是一个独立的必需服务或仓库。人类和其他工具可以直接使用 Loom。一个 Weaver 实现可以生成普通软件，或遵循 Loom 之外的其他指南。要声明符合某个选定的 Loom 合约，它必须满足该合约；它不能在实现后静默地丢弃失败的检查或选择较弱的规则。规则变更需要一个新的经过审查的基线。这是目标策略，而不是一个新的可选配置文件 CLI。

优先考虑可用的 spool 生命周期和托管合约。进一步的自主 Weaver 协调需等待实际的开发需求；下一个 spool 切片不需要新的模型循环或提示拦截服务。
