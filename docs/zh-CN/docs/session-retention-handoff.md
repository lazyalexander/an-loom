# 会话和留存开发移交

[English](../../session-retention-handoff.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

状态：原生输入参考移交已通过；剩余的留存/会话工作是一个协调计划。现在，一个宿主拥有的有限队列/分发适配器已与包装的事件案例配对。初始移交不需要任何清单、运行时授权或包格式的更改。GUI和TUI推迟处理。本地无头执行仍为资格目标。

宿主的[会话和留存计划](https://github.com/lazyalexander/an-agent/blob/dev-advance/doc/session-and-retention.md)对运行时范围具有权威性。正式的 artifact 参考发布/收集与队列协调无关；关闭一个队列不会释放任何 artifact 参考。现有[原生 spool](native-spool.md)合同仍为实现表面。

## Loom 的部分

Loom 帮助作者描述输入、输出、显式检查点要求、有用受限上下文和领域接受。它检查并打包选定的字节，将执行请求传递给宿主。留存意图不是删除权限；声明不能创建授权、参考释放或模型预算。不要在 Loom 中添加运行时会话管理器、PIN 存储、收集器或模型循环。

领域项目应区分输出来源与仍需原始字节的依赖项。状态保持不可见：作者必须在最终合格检查点合同中明确声明所需 artifact 参考，而不是期望宿主从文本中推断。不要在宿主合同存在之前添加推测 manifest 字段。人工编辑的产品是一个新修订版本；摘要是一个推导的上下文视图，而非权威业务状态。

一个 spool 激活使用实例身份和轮次生成进行地址。使用 `cohort create|run|show|control` 表示一组有限分发，使用 `spool-supervisor dispatch WORKSPACE COHORT DISPATCH show` 表示一个成员。遗留命令和 JSON 字段名保持兼容。 neither 队列 nor 分发选择模型对话。会话携带私有交互历史，一个线程标识其系统内执行或对话，上下文是选择的材料，工作区保存版本和事实。现有编码代理保留其自己的会话、压缩和磁带。Weaver/harness 适配器交换明确选择的材料和候选变化；它们不能爬取私有历史或默许分享对话。原生 harness ID 保持私有，不能授予对工作区的访问权限。对于宿主模型 CLI，包受众识别接收的代理。对于原生对等请求，它识别接收的 spool 实例。一个队列或分发名称不能替代 UUID。

对于受限对等请求，编写一个包含 `an-context-v1` 的小声明 UTF-8 输出，该输出指向预期接收 spool 的实例 UUID。使用 `an-native-peer-context-request-v1` 选择该输出。宿主检查 4096 字节的无线限制，并要求两个端点生成和分别执行批准。一个队列及其一次性分发控制工作。一个核心代理的私有磁带、一个 harness 对话和一个 OS 工程员各自拥有自己的身份。作者不能从这些名称推断受众。打包的日志固定只在发送者 scratch 收集后交付选定的第一行。其完整输出和工作区事实日志保持分离。

接收器可将`silk/agents.json`加入其现有的不可变SILK列表中。头less手off支持一个JSON数组，该数组包含1到8张无工具的v1核心代理卡，这些卡具有独特的UUID。当操作员预览和批准`spool-peer deliver-agent SOURCE REQUEST AGENT_UUID`时，宿主重新检查释放成员资格，并验证已结算的对等方输入。选定的卡将获得一个全新的本地套件会话。单独的宿主模型批准可以将结果包发送到特定的终端。打包罗列或选择一张卡不会提供模型访问权限。Loom使用其正常的归档和原生导出；配对的资格检查，一个兄弟不能使用选定的批准。

工作区存储版本化的材料和事实，而不是对等方的对话。项目必须使用显式的授权协议交付，即使当数据以文件形式传输时也是如此。私有笔记不能变成隐式的命令或系统指令。上下文选择保持领域/套件行为；宿主分别授权访问和模型披露。共享一个套件环境并不能提供其内部代理之间的硬隔离。宿主的当前原生配置保护未选内容，但允许文件元数据；它不承诺存在性保密。Loom必须不能通过声明来声称更强的隔离。

宿主通过两个真实CLI套件验证惰性私有笔记、跨实例内容拒绝和分阶段产物请求/回复。配对打包的示例提交一个已验收的输出，运行目标，接受其声明的回复，然后运行请求者针对该固定版本。等待是宿主记录，而不是占用的进程。回复绑定精确实例/释放身份及其现有的轮次控制生成。暂停/恢复一个实例会隔离旧端点。没有包模式或新运行时权威被隐含。

Loom提供入口点和声明输出；受信任的宿主分别授权请求、回复和执行。不要生成直接宿主CLI访问，共享目录轮询或私人工作区邮箱。实时IPC、全局等待调度、套件/模型上下文交付和成功对等方输入-pin释放保持未资格。宿主拥有失败矩阵；Loom检查一个真实导出的释放轮询和不变的工作区事实。一个对等结果只有在普通宿主接受步骤之后才正式。

## 所有者拥有并独立监督的执行

宿主的遗留前台`spool-start`资格显示，SIGKILL终止启动的CLI会留下工作进程在截止日期之后运行。处理的SIGTERM保留原始监督者，该监督者确认整个组的终止。在SIGKILL之后，晚文件和外部观察到的进程退出仍不足以证明接受或收集。从可丢弃测试固定中移除过时锁仍会拒绝这些操作。

开发工具必须保留原始尝试身份，并在该监督者证据缺失时报告未知结果。它们必须不重新运行命令、接受晚文件、删除scratch材料或移除操作锁，以将中断的交互转化为成功。检查可以保持可用。

宿主现在为原生文件输入、精确检查点和组合数据/状态提供显式的尝试范围监督，通过`spool-supervisor`（`start`，`start-state`，`start-data-state`，`show`，`cancel`）（执行和接收合同）重用执行和接收合同。Loom提供包和请求身份，并接收验证结果。监督启动、进程所有权、取消和恢复属于宿主。新的包字段、Loom守护进程或模型集成对于此资格是不必要的。

打包事件接受也运行未修改的发布版本通过该监督启动，检查原始终止证据，接受其精确输出，并验证在私有收集后保持不变。宿主CI拥有客户端SIGKILL，继续截止日期/取消，监督者死亡和不确定结果拒绝。原生CLI现在同时提交Peer阶段和事件交付到同一尝试监督者。有限宿主控制器拥有每个批准的批次或群集分发。三轮打包日志案例杀死事件客户端，取消其原始尝试从另一CLI，验证整体结算。它分别杀死实际尝试所有者并验证保留，零重放情况下。Loom打包普通入口点并检查宿主证据。宿主拥有取消、截止日期和决定是否接受下一个入口。

显式检查点运行可以使用 `spool-supervisor start-state` 与精确的修订版本。Loom 的原生状态接受运行通过此入口导出 v1/v2 发布版本，并保留现有的状态提交和托管检查。宿主拥有客户端损失、取消、截止日期和旧修订版本与新 HEAD 之间的测试。

打包的日志累积器验收使用`spool-supervisor start-data-state`作为其直接合并运行。宿主在批准时保留精确的业务/检查点绑定，并在执行前重新验证准入。Loom 保留请求材料作为选择JSON，而非共享可变运行时控制。现有状态冲突、已接受产品和参考保留的断言保持不变。宿主测试自身客户端/监督者丢失以及预留到工作节点的变更窗口。

## 分阶段兼容性工作

1. 包装日志案例现在会将宿主拥有的数据/状态声明与精确修订版本和导出的发布版本进行比对，保留这些信息通过收集和卸载过程。包装事件案例也检查在已接受输出之后的显式状态无状态成功参考发布版本，原始消费确认和私有收集。宿主还根据已批准的spool政策和全面输入覆盖范围，对成功的组合事件发布进行资格审查。其他状态化所有者、不可见依赖项和遗留/未管理的读者保持保守保留。宿主测试自身的中断、竞争和损坏；loom不从参考观察中推断删除权限。对于已退役的输出，宿主可以将源标记与显式选择的消费者收据进行交叉验证，使用`spool-artifacts ... --review-retirement`。缺失或外来的完成情况仍不确定，检查点针保持持有。选定输出检查（`spool-artifacts ... --output OUTPUT`）验证原始库存和一个载荷。一个缺失的兄弟载荷不会无效该检查；缺失的兄弟元数据仍然有效。整机托管仍严格。现有目录具有未管理的读者，因此零声明不授予删除权限。loom使用宿主合同，拥有无读者库存或收集政策。
2. 在首次接受时，操作员可选择宿主注册的复制配置文件。它从出版物中注册读者。原生事件可将该精确版本交付到私有尝试快照中，同时与显式选择的检查点一起。宿主拥有准入、确认发布和删除收据。在配对的三轮日志示例中，检查点保持第一批次，确认取消允许收集不同输出，丢失实际尝试所有者则使其版本保留。示例随后显式退订最初注册的检查点并通过收据释放其针。过时事件批准失败，当前检查点仍可选择。遗留目录保持保留。
3. 包装事件案例现在使用`cohort create`，已通过校验的`cohort run`，`cohort show`和`cohort control ... closed`，然后接受并移交其产品。其遗留线程记录绑定一个有限的分发；固定状态选择仍保留在现有分发请求中。宿主CI拥有重叠的群体取消、过时的代际和缺失的证据。同时，同一工作空间的同工作量准入仍为fail-fast；没有自动重试、后台调度器或loom侧生命周期政策。没有包字段发生变化。
4. 重用显式上下文包和受限收据关联的导出。验证预期受众和源身份，记录字节和模型调用次数，并区分测试证据与实时提供者使用。未知使用不为零；文档不得承诺无证据的测量令牌节省。
