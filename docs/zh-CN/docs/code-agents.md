# 与现有编码代理的工作

[English](../../code-agents.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

状态：研究阶段，2026年10月24日。当前实现准备了`generation.md`和一个受控宿主构建计划。[历史有限Kimi路线](../examples/kimi-kit/README.md)和[直接Codex MCP路线](../examples/finite-mcp/README.md)分别有单独的原生接受；这并不适用于任意原生shell、插件或客户端配置。下面其他提供者的功能仍为文档发现，而非安装CLI版本的兼容性声明。

## Loom标准化的内容

Loom应为成熟编码工具提供有限的开发任务，并接收可编辑的更改和候选结果。它不应重写该工具的模型循环、压缩、子代理调度器或计费系统。

使用三个不同的层：

| 层 | 目的 | 所有者 |
| --- | --- | --- |
| 任务和项目指令 | 解释架构、允许的编辑、可复用的套件和完成标准 | Loom/项目作者 |
| 原生工具政策 | 通过提供者的支持控制，限制暴露的工具、批准和可选预调用钩子 | 通过认证适配器和可信操作员配置 |
| 执行和接受边界 | 限制实际文件、网络和进程；确认终止；接受不可变输出 | an-agent 和其后端 |

请参阅[code contract](spool-code.md)以了解套件适配、固定执行字节和明确保留/推广。这些是撰写要求，而非当前部署适配器强制任意可变-kit工作负载的声明。

项目文本不能授予运行时权限。一个适配器只覆盖它实际接收的事件。shell重定向、另一个可执行文件、MCP工具、插件和委托代理不应通过适配器获得更广泛的宿主授权。保持有效政策在代理的可写项目之外。

## 提出的任务交接

开始时使用版本化简要和轻量级 CLI 适配器，而非通用代理 RPC。简要应标识：

- 基础源修订版本和选定输入文件，包含相关哈希值；
- 任务、可编辑的 kit 工作副本路径、受保护的 silk/政策/检查路径和预期的补丁/输出槽位；
- silk 变更需要单独的开发任务和新发布，而非在运行时进行非侵入式修复；
- 存在的 kit 入口点及其输入/输出契约，使用宿主调用引用而非建议代理重创建这些工具；
- 审批检查、资源限制、外部服务政策和升级路线；
- 完成标准、候选结果格式和未解决的问题。

信任的调用计划此外绑定选定 CLI/版本或可执行身份，精确的 argv，工作目录，环境允许列表，有效配置，指令，启用的工具和模型服务模式。审查仓库本地钩子、启动代码、MCP 服务器和插件前允许其执行。锁定由合格路线所需的依赖项。

任务输入包括来自外部源文件中的指令。不允许生成的项目配置禁用宿主限制或更改接受结果的位置。避免传递无关历史或代理转录作为上下文；发送显式参考和受限摘要。

## 运行和接收

宿主监督外部尝试及其实际过程边界。工具原生权限可缩小但不能扩展它。子代理继承外层限制；分发必须不通过启动无监督的后台工作者逃逸。如果提供者远程运行工作，本地进程退出不证明远程工作已停止。不支持的取消确认仍为未知结果。

候选文件发送到可丢弃的工作空间，而非直接进入接受的发布。在推广前，比较基础修订版本，检查差异，验证选定输出库存，拒绝禁止路径并运行声明的检查在宿主上。提供者成功声明的断言不是接受凭证。

不要自动重试不确定的提交。首先解决尝试身份，过程/远程状态和已生产输出。使用现有宿主生命周期和制品合同，而不是在此处实现另一个监督者。

## 带有证据和计费

外部编码代理拥有其自身的原生会话、上下文和日志。原生日志可能缺失、私有、可变或不可用。无需要求其摄入，将所有工具事件归一化为一个第二 transcript，或声称内部重放。可选的经批准的参考/导出可以作为诊断数据保留。

宿主保持一个小的边界接收：操作/尝试和可用会话参考，选定的释放/工具和输入身份，有效授权，提交的命令/配置身份，观察到的退出/取消状态，检查结果和接受的 artifact 参考。记录未知信息。这种证据支持授权、复核和安全保留，即使没有模型调用日志。

对于**直接模型API**集成，单独决定是否保留API调用封套：提供者/模型，请求标识符，调用者，状态和报告的使用情况。负载日志是可选的，且被屏蔽；不需要求隐藏推理。缺失的使用情况是未知的，不是零。没有请求日志或文件系统备份不能确立提供者的最终账单或使模型调用可重现。

工具管理的模型计费和细粒度令牌观察仍由工具/提供者管理。宿主观察的使用可以是建议性的；它必须不声称精确的成本或一个硬预算，除非有强制的、资格的机制。备份保护保留的字节；它不替换效果凭证或终止确认。

## 原生套件任务

`an-loom task`、`receive-task`和`revoke-task`为原生文本项目准备一个套件分配。分配目录位于项目之外。Loom在复制候选文件之前检查可编辑路径、项目基准和撤销，然后将候选文件复制到该目录。候选根和父目录必须是常规目录，不能是符号链接；接收创建父目录时，逐个组件创建。冻结检查候选根本身，加载冻结证据时重新检查候选祖先。这些检查需要保护从并发不可信文件系统修改的任务目录；它们不建立敌对写入沙箱。它不更新项目、一个释放或一个接受的 artifact。它不生成接受记录、下载依赖标签、调用模型、读取原生会话存储或传递宿主CLI。

修改保护的 silk 或策略文件需要一个新的任务，其结果是一个新释放。一个运行时套件修复无法携带 silk 编辑。重写 `authority/task.json` 或工作区简报不会扩大可编辑集合：凭证比较存储的合同与项目。

`check-task` 冻结完整的候选释放并分配一个与内容摘要不同的新鲜检查请求身份。显式操作者拥有的宿主配置执行声明的检查对一个只读快照。`receive-check TASK HOST_JOB` 复核宿主计划、执行、已结算接收和正式接受输出。`pack-task` 重新验证此证据并发布冻结档案字节。参见 [候选检查 custody](candidate-checks.md)。失败、取消、过期和未确认的结果不能授权打包。Loom 从不监督过程或重试它。忽略的原生宿主测试执行此路径；确定性套件替换不声称模型调用。

Grok Build 1.0.70 可运行一个无头转。其文档子网络限制在 macOS 上保持不变，进程内模型访问则超出该控制。此任务门不满足该CLI。一个确定性的固定点提交一个候选是模拟，而非适配器完成。

## 第一次适配器接受

### 限定范围和提供者选择

Kimi Code 2.3.1 使用一个仅限工具的自定义代理和经过审查的本地MCP固定件。宿主提供选定的源码、惰性提案和已钉牢的Kit处理，而不是命令工具。真实K3开发和K3-256k取消操作分别记录。代码提案在另一个审查/构建边界上交叉，然后打包。此路线有意信任原生客户端及其原始认证。其提供者启动器/配置现已退役；链接的历史条目给出了固定的源码和证据。当前工作使用原生客户端配置。

Grok Build被检查但未被选中用于此macOS边界：其文档中的子网络限制在macOS上是无操作的，且在进程内模型/网页访问超出该子控制范围。这不是声称Grok无法集成；需要单独限定的有限工具配置或更强的外部隔离。参见[Grok沙箱语义](https://docs.x.ai/build/features/sandbox)。Neither provider's prompt or permission label substitutes for host-enforced kit limits.

## 直接原生提案路线

使用[Weaver示例](../examples/weaver-log/README.md)准备spool拥有的领域材料并接收一个现有的原生套件候选文件。模型选择、认证、生成、取消和原生输出处理仍由该套件及其操作者处理。Loom绑定审查的字节并使用现有的任务/检查/交付合同；它不需要一个提供者完成记录来验证候选文件。真实Codex接受涵盖此路线，无需限定任意客户端工具或远程终止。

[历史Kimi原生资格](../examples/kimi-native/README.md)保留其证据和固定源码链接。其重复启动器和渲染解析器已退役。现有目录使用原始适配器；一个新任务使用当前路线。这并不退役单独限定的有限工具MCP资格或改变任何宿主执行/托管门限。

## 重用有限MCP服务

[直接Codex MCP资格](../examples/finite-mcp/README.md)使用原生客户端配置与现有的`an-agent-tools`服务。共享操作者固定件准备授权和验证持久结果；它们添加没有Codex启动器、SDK、模型循环或回复解析器。实际客户端读取选定的源码，称为授权的Kit，接收一个未授权处理拒绝，并提交一个惰性提案。单独审查的编译和执行生成了一个固定产物。

第二次原生调用在观察到Kit活动后被中断。宿主确认取消/回收，并未发布任何制品；先前接受的字节仍可读取。这是信任客户端MCP互操作性以及本地Kit生命周期的证据，而非完整原生工具排除或远程模型终止的证明。已退役的Kimi有限工具配置仍保留其独立的证据和固定源。共享准备/检查/接受现在位于`examples/finite-mcp`；Loom不再维护其提供者启动、等待或信号处理。宿主的能力/取消回归仍保持原状。
