# 原生开发到已加载的spool

[English](../../develop-native.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

`develop-native` 将现有的候选者和宿主合约组合成一个可信的操作员。它不实现代理循环或新的执行后端。

```sh
an-loom task ./project ./task
# A person or coding tool submits the assigned replacement.
an-loom receive-task ./task kit/transform.sh ./replacement.sh
an-loom develop-native ./task HOST_CLI ./check-job ./delivery
# Review the printed profile, acceptance commands, steps and selected host hash.
an-loom develop-native ./task HOST_CLI ./check-job ./delivery --approve DIGEST
```

预览会冻结候选对象并准备其档案，但不会执行项目命令、创建任务/交付或加载spool。批准涵盖一次有限检查，条件性的正式接受其声明的输出、证据接收、字节相同打包、显式v2导出和非执行宿主加载。每个宿主调用仍使用现有的预览/批准合同。
选定的宿主可执行文件由现有的传输进行哈希和重新检查。

成功的结果命名了被检查的存档、可移植的`spool/`目录、本地的`instance/`、发布标识和宿主检查尝试。该实例被加载而没有执行权限。单独检查和批准`spool-start`。因此，新的条目验证了这台机器是否可以接受交付的v2档案；普通的导出仍然可用于打包而无需本地接受。

交付布局如下：

- `spool/`：选定的不可变v2内容，适合交付。
- `project/`：单独的候选项目和精确检查的发布存档。
- `instance/`：本地宿主拥有的加载实例；不要将其作为源代码分发。
- `intent.json`、`host-*.json`、`result.json`：本地操作证据，可以包含绝对路径。请将这些内容排除在公开发布材料之外。

## 单次提交和不确定的结果

任务和交付必须是源代码/任务之外的新鲜同级/非重叠路径。适配器在提交前关闭`authority/develop-native.json`。提交的任务不能再次使用该条目，即使目的地不同。失败的检查、传输错误、检查后打包/接受失败以及中断的客户端保留可用证据，不会自动重试或清理。

使用现有的托管/状态工具检查保留的宿主任务（检查任务是一个工作区任务，而不是spool实例）。在证据允许的情况下，显式手动协调可以使用现有的单个命令；此条目不是自动恢复引擎。如果客户端消失，不要推断宿主或外部工作已停止。现有的传输是一个受信任的本地CLI传输，而不是新的取消监督者；宿主执行保留其自身的截止时间和取消行为。不要将此操作条目暴露给不受信任的编码代理作为无限制的命令工具。

此便利条目适用任务接受围栏。它不是针对操作者故意调用低级命令的文件系统沙箱。未知结果需要在新任务授权前进行检查。

## 合格性

支持的路径仍然是经过审查的shell档案（[平台矩阵](platforms.md)），不包含网络或GPU，15个项目输入文件加一个运行器和30秒的检查截止时间。依赖项未被安装。不支持的声明可能被打包但会失败本地宿主接受，保留中间结果。仅语法接受的项目仍然是仅语法检查；领域测试仍然是作者的责任。

真实的原生spool测试创建一个确定性替换，检查特定候选对象的领域条件，交付/加载它，单独执行该实例并检查其正式输出。它还验证预览和被拒绝的批准不会提交，已知失败阻止发布，并且之前的提交围栏防止在成功/失败或模拟中断意图后重试。中断意图的测试套件不声称进行真实的进程终止实验。不声称有任何模型调用。现有的v1/v2生命周期测试仍然启用。
