# Spool 发布到宿主的交接：首次实现切片

[English](../../spool-runtime-handoff.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

状态：初始原生 v2 实现加上更广泛的宿主合同。原生 v1 保持不变。详见 native-spool.md 获取确切的合格编码。GPU 和外部应用支持仍为未来功能。

## 当前实现中观察到的问题

原生创作记录了运行时、输入、可编辑的工具包路径、能力和依赖项，但 export-native-spool 会从执行清单中删除这些内容。宿主提供了一个固定的已审核的 macOS shell 配置文件。这对于其合格的测试装置来说已经足够，但无法代表一个普遍可加载的 spool 合同。

## 所有权

Loom 验证并导出请求的依赖项。宿主独立检查所选的完整发布版本，并决定准入和执行授权。清单指令或包验证不授予任何权限。领域接受仍保留在 spool 中。平台特定的启动和封装仍保留在后端中。

## 提议的原生 v2 扩展

保留 v1 字段，并添加一个必需的 `requirements` 对象用于 v2：

| 字段 | 含义 | 初始合格性 |
| --- | --- | --- |
| runtime | 所选执行配置文件标识 | macos-native-process-v1 |
| os | 目标操作系统 | macos |
| arch | 目标 CPU 架构或显式便携源 | portable-source 用于已审核的 shell 测试装置 |
| interaction | 无头或外部应用 | 无头 |
| gpu | 无或必需，带有提供者/运行时约束 | 无 |
| inputs | 声明的输入插槽 | 一个文本插槽用于现有宿主路由 |
| editable | 作为工作副本允许的发布相对工具包路径 | 所选工具包负载的子集 |
| capabilities | 请求的效果 | 仅固定配置文件实际提供的效果 |
| dependencies | 执行前需解决的外部运行时依赖项 | 没有未解决的额外依赖项 |

首次编码使用字符串表示 runtime/os/arch/interaction/gpu，使用数组表示 inputs/editable/capabilities/dependencies；GPU 目前仅支持 `none`。未来 GPU 提供者约束需要一个单独版本的合同。不要从包名推断操作系统/架构/GPU 能力。不要添加独立的 YAML 权威文件：任何可读的 YAML 必须源自或明确绑定到此内容标识的合同。标签本身不能建立兼容性或依赖项可用性。

## 准入和执行

在创建实例之前验证模式、角色、路径和完整库存。在启动前验证目标环境和所需能力。未知的必需能力、不支持的 GPU/interaction 要求和未解决的依赖项必须明确拒绝，不能静默回退到原生访问。将请求的要求与有效的授权分开显示。在批准启动时重新检查实例、发布、输入、工具包版本和执行环境。

无头和 GPU 是独立的维度。一个 GPU CLI 可以直接在合格的计算后端上运行。一个中继器调解授权的外部应用或文档交互，无论该应用是否使用 GPU。一个微虚拟机是一个可选的后端；GPU 可用性必须针对该实际后端进行验证。一个外部任务需要其自己的结算证据；本地进程退出不能证明应用或远程工作者已停止。

Linux 必须重用发布/实例/尝试标识和产物保管。保持 macOS 路径和启动策略在平台适配器中。不支持的 Linux 执行必须保持不支持，直到经过测试；便携包装不意味着便携执行。首次切片不添加任何新的后端或依赖项安装程序。

## 兼容性

保持原生 v1 导出/导入和现有 CLI 行为可用。使用显式的 v2 选择来满足新需求；不要重新解释历史 v1 字节或发明缺失的权限。v1 宿主必须拒绝 v2。v2 要求参与版本标识，因此权限更改不能保留旧版本标识。绝不要自动继承旧版本的执行批准。

## 协调实施和接受

1. 冻结一个小型的公开有效/无效 v2 测试集和对应的生产者/宿主测试。保持两个仓库的运行时独立。
2. 在 Loom 中添加显式的 v2 导出，并在宿主中实现严格的 v2 验证/准入；保留 v1 测试集和确定性标识。
3. 运行一个真实的宿主循环，使用相同的窄文本 spool：导出、加载、预览、批准、执行和接受固定版本输出。
4. 验证操作系统不匹配、未解析的依赖、未知能力、受保护的可编辑路径、GPU 要求和外部应用程序要求时的拒绝行为。拒绝时不能启动或发布输出。验证更改的要求会使之前的版本/批准标识失效。
5. 发布配对的 PR，包含固定跨仓库 CI 提交和实际证据。在该执行接受通过之前，不要标记第一个切片为完成。

Loom 当前的 shell 检查流程有单独的 15 个项目文件和 30 秒的限制；在此切片期间，不要扩展这些限制以适应新的工作流程。
