# 日志报告：支持、耦合和领域所有权

[English](../../log-report-workflow.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

示例 [example](../examples/log-report/README.md) 会从合成日志生成可编辑的工作簿和演示文稿。其命令行工具套件也可以在不依赖 Loom、an-agent、Nextflow、模型 API、GPU 或 Office 安装的情况下运行。可重用的支持是通过一个可选的宿主适配器进行测试，而不是导入到业务工具套件中。

## 边界

| 类别 | 可接受的责任 | 本示例中的边界 |
| --- | --- | --- |
| 支持 | 通用的有界字节保管、血缘、固定输入、终止和保留 | an-agent 宿主，不依赖 Office 或工作流引擎 |
| 显式耦合 | 一个可替换的格式/协议适配器，具有明确的合同和资格范围 | 示例中的 openpyxl/python-pptx；可选的宿主 CLI 适配器在 `kit/` 之外 |
| 侵入 | 领域假设成为通用组件的必需行为 | 日志字段、百分位规则、工作表列、幻灯片布局和 Office ZIP 解析不得进入宿主/核心或 Loom |

Loom 会检查并打包选定的源；它不会成为运行时调度器、Office 服务或模型循环。该包使用通用内容路径，保持固定的 Rust 文件工具套件部署适配器不变。模型叙述可以通过授权服务成为未来的领域阶段；不需要模型来计数请求或将保存的评审注释带入报告。这种接受不进行任何模型调用。

## 接受证明了什么

真实的宿主路由在现有的 macOS 工作区 profile 下运行经过审查的 Python 工具包。显式的二进制输出变为不可变的字节修订版本。一个可编辑的副本会被保存并提交，同时包含父版本和已批准的摘要。之后的编辑会创建另一个修订版本；下游的 profile 仍然绑定所选的较早修订版本和快照。在执行前替换该快照会被拒绝。被接受的 PPT 来源标识了确切的输入修订版本，且原生的可编辑文本/表格对象包含所选的审查注释。

测试通过文档库模拟保存的编辑。它并不声称有人操作了 GUI，也不验证谁编辑了文档。一个真实的电子表格编辑器可以在不改变宿主合约的情况下替换该保存步骤。提供的工作簿可以在 Office 兼容的应用程序中打开/重新计算；下游的验证不依赖于公式缓存。

仅在真实 PPTX 存在且进程仍然活跃时才会发生取消操作。活跃、取消和延迟替换的候选对象都会被拒绝。原生的终止操作会被确认；不会创建任何部分正式修订版本。被已验收的输出会存活于显式的临时收集操作中。仅文本输出声明会拒绝相同的二进制字节。领域解析/可编辑性检查与宿主字节身份是分开的，无法保证每个 Office 文档都安全打开。

## 执行环境范围

宿主的第一个模块迁移将身份/结算与具体的后端机制分离，同时保留路径和行为。它不添加任何虚拟机、容器、暂停、快照或编排服务。位置、操作系统和隔离类型仍然是独立的能力维度。未来的后端必须能够实现实际的终止及其自身的恢复保证；进程沙箱不能默默地替代虚拟机需求。

原生的工作区配置文件是针对经过审查的本地工具，不包含守护进程，而不是一个敌对的编码代理沙箱。完整的宿主托管接受仍仅限于macOS；独立工具检查在Linux和macOS上运行。CPU Linux是部署方向，而不是对此宿主配置文件的扩展声明。

## 观察到的适应性证据

第一次原生尝试导入 openpyxl 失败，因为 Python 的 MIME 注册表试图读取 `/etc/apache2/mime.types`。该尝试失败并终止，但接收结果被保留下来。
一次全新的显式尝试使用了内置的 MIME 注册表以及库的 OOXML 注册表，初始化在 `kit/ooxml.py`。没有扩展任何沙箱规则或宿主权限。这是可替换适配器中的一个具体库兼容性细节，而不是针对某一文档库的新宿主策略。

便携式结果记录在 [接受记录](../../acceptance/log-report.json) 中。
原始配置文件、机器路径、进程日志和开发探针将保持私有。
CI 集成选择了一个固定的宿主源版本；它不会向 Loom 添加宿主运行时依赖，也不会向 Loom 依赖项添加 an-agent 依赖。
