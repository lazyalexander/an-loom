# 仓库质量门

[English](../../quality.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

`cargo quality --base origin/dev-advance` 通过一个小型的 Rust 操作符适配器运行固定的 SPACE 架构检查器。该检查器是其自身工作区中的一个开发依赖项；它不会链接到 Loom 或部署的 spool 中。上游源代码和许可证仍保留在
[SPACE 版本 57c7c0c](https://github.com/perplexityai/SPACE/tree/57c7c0c47a73373a974c5b542d180599795465da/crates/tools/archcheck)。
这种重用不会引入任何 SPACE 运行时或控制平面依赖项。

- `ARCHITECTURE.toml` 对生产 Rust 文件的行数限制为 500 行，将新命令的构建限制在 `src/adapters/`，并拒绝模糊的 crate 名称。
- `architecture-baseline.toml` 从不接受异常。必需的 ratchets 拒绝新增的异常、提升的上限、增长和过期条目。重命名比较是基于显式的 Git 基础。
- `quality.toml` 禁止在运行时依赖于 host/core/domain 实现、架构检查器和直接的 HTTP 编排。Loom 通过显式的合约委托执行和建模，而不是拥有另一个运行时。

当缺少历史记录、未知的策略字段或跳过了必需的检查时，包装器会失败关闭。策略更改需要单独的审核迁移。初始引导仅识别两个预策略仓库树，包括一个等效的合并/压缩；它不接受任何基线例外。未来的基线必须携带已提交的规则。它不能从一个移动的分支名称静默引导。

Linux 和 macOS 的 CI 都运行门和检查器测试。变异测试展示了对过大源代码、未经调解的命令构建和弱化策略的拒绝。隔离的检查器也会进行 fmt/test/clippy 测试。运行时测试和现有的真实 host/Nextflow 验收测试仍然是审查纪律所必需的。此次更改不会削弱任何分支保护设置。

这些是源代码结构和依赖项检查，而不是语义沙箱证明。不要机械地分割一个连贯的文件或添加基线豁免以使功能通过。审查责任边界并把效果移动到显式的适配器中。任意的领域负载不会仅仅因为被 Loom 打包就成为 Loom 的实现。

使用实际的 PR 目标作为显式的比较基线：开发使用 origin/dev-advance，稳定发布使用 origin/main。无参数的检查器保留其 legacy origin/main 默认值；贡献者必须显式选择预期的基线。此次分支工作流程不会更改任何策略字段或基线。

开发和稳定 PR 都运行完整的现有 CI 矩阵。开发需要所有五个当前状态上下文、最新的分支、PR、已解决的对话以及无强制推送/删除。主保护保持独立且不变。
