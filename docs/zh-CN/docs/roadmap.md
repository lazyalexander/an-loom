# 研究与下一阶段接受切片

[English](../../roadmap.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

此页面保留了研究问题和工作流程观察结果。使用[开发轮次](development-rounds.md)来表示已完成的作者/检查切片，使用[原生spool](native-spool.md)来表示当前配对宿主的资格。研究目标并非执行的保证。保留现有的检查。

## 术语

使用**工作流程**来表示领域过程，包括分支、代理和人类决策。使用[代码契约](spool-code.md)：**silk** 标签每个不可变的发布基准文件，**kit** 标签可变衍生品和新工作，**spool** 是可部署的领域载体。不需要额外的机器抽象或执行引擎即可采用现有工作流程。一个工作流程不必是静态的有向无环图（DAG）。

## 1. 建立spool更新身份

研究精确的发布身份、授权的线性关系、兼容性以及实例身份分别。起始发现和拒绝情况见[spool-identity.md](spool-identity.md)。在添加manifest字段前，复用包坐标、SemVer（如适用）以及供应链证据概念。交付一个小的本地更新接受：两个发布在一个授权的线性关系中，一个未经授权的后继拒绝，一个明确的能力增加决策，以及一个失败的状态迁移，同时保留旧检查点。Loom包提供证据；宿主拥有准入和实例转换。不要从匹配名称、UUID、版本标签或模型意见推断等价性。

## 2. 观察一个现有的工作流程及其文件

初始候选：[Nextflow](https://github.com/nextflow-io/nextflow)，使用上游的[hello workflow](https://github.com/nextflow-io/hello)作为小引擎探针。其[源码](https://github.com/nextflow-io/hello/blob/master/main.nf)包含四个问候任务，带有stdout输出。它本身不是一个现实的领域管道，也不是一个文件输出/代理接受本身。保留这个限制。

此处开始的原因是其现有的工作/缓存/恢复机制。Nextflow的[恢复](https://docs.seqera.io/nextflow/cache-and-resume)需要任务元数据和任务工作文件。其[报告](https://docs.seqera.io/nextflow/reports)提供独立的执行诊断。我们应该观察这些，而不是用代理实现替换其调度器、任务缓存或原生日志。

通过正常、中断和恢复运行已观察到原生执行。见[证据和限制](nextflow-observation.md)和[可重复性示例](../examples/nextflow/README.md)。在准备过程中安装了Java和一个校验和已锁定的分发版本；执行保持离线状态。配对宿主的工作空间配置文件与狭窄的Rust构建和文件-kit部署配置文件不同。没有隐含的任意JVM/spool运行时支持。

可重复性观察记录了在中断尝试前、中、后以及之后的文件。记录相对路径、大小、哈希值、文件类型和生产者/尝试身份，而不发布私有内容。视符号链接、硬链接和仍在写入的文件为危险，用于接受检查。

| 文件类 | 预期处理方式 | 验收证据 |
| --- | --- | --- |
| 已钉定的工作流程代码/配置和不可变输入 | 仅读取式发布/输入材料 | 选定的源代码和输入摘要保持不变 |
| 任务工作文件和引擎缓存 | 默认为临时文件；在明确的恢复租约下保留 | 在保留期间继续工作；收集后无虚假恢复声明 |
| 原生执行日志/报告 | 有限制的私有诊断，除非明确导出 | 收集状态、保留截止日期和红密决策 |
| 已声明的交付成果 | 作为宿主接受的候选；之后变为不可变的构建版本 | 关闭输出清单、验证字节和生产者身份 |
| 代理会话/磁带，如果存在 | 工具所有私有数据；可选明确引用 | 无需要求传输记录或完整性声明 |
| 证书和机器配置 | 外部于载荷中的可信服务配置 | 不复制到发布或制品中 |

未更改的 hello 探针通过带标签的包装器导出问候结果。
一个独立的本地文件生成固定件可满足输出准入、实际 CLI 中断、三任务缓存复用和固定版本生存需求。
该内容明确不是上游代码或成熟领域工作流。

同伴 **an-agent 文件管理切片** 遵循观察到的边界：

1. 尝试为工作区分配一个可丢弃的临时区域，并使选定的输入保持不可变。
2. 使内部路径对下游的spools保持透明；仅接收声明的输出。
3. 在观察到终止后，验证/复制/哈希输出并提交一个已识别的接受记录。文件事件仅作为候选信号。
4. 保留检查点/输入参考，待交付参考和显式恢复/调试保留。未知终止或可能的远程写入者禁止收集scratch。第一个配置使用手动放弃；受限租约和调度仍为未来工作。
5. 收集可接受的scratch，不影响已已验收的产物；拒绝延迟输出和测试部分写入、失败输出检查和重复接受。

库存必须在接受时进行核对；文件监视器不能建立文件完整性或一致的检查点。首先重用当前宿主制品、检查点和保留机制。仅添加观察显示的间隙。
工作特定文件语义保持在适配器/spool中。

## 3. 允许无中心化的磁带

对于第一个代理辅助工作流，操作员提供推理/编辑步骤。使其受限输入、输出和权威可见；不发明一个自主调度器，仅为了移除这个手动步骤。区分此与一个活码代理适配器的接受。

## 4. 限定現有編碼工具

外部代理管理自己的磁帶。保持主機邊界憑證和可選的會話參考。直接API呼叫元數據是另一個可選選擇；文件系統備份和提供者賬務各自保留其目的。詳細內容和未知結果處理見[code-agents.md](code-agents.md)。

使用一个任务合同，并通过[直接原生嵌入路线](../examples/weaver-log/README.md)处理已审核的提案。当已有客户端能够生成候选文件时，不要添加启动器、回复解析器或提供者目录。仅在直接路线无法表达的观察到的宿主能力或策略边界上添加资格适配器；有限工具MCP资格属于此类单独情况。

[调查与验收](code-agents.md)涵盖Codex、Claude Code、Kimi Code、Grok Build和Gemini CLI。从一个已安装的工具和轻量级套件开始。在声称控制集成前，必须提供实际的拒绝和取消证据。在研究过程中，不要默许选择模型或上传工作空间。

## 序列与范围

继续身份研究，选择第一个权威政策。第一个引擎观察和最小宿主文件边界现在有验收证据。在自动化之前，使用填充操作员的代理步骤。将一个成熟代码适配器资格认证与同一边界。这些可以共享一个固定，但需要单独的证据。

这些切片中不包含新的核心引擎、VM框架、通用工作流程DSL、转录服务或提供者计费系统。应基于观察到的失败更新此计划，而不是预先构建通用框架。运行时变化应包含在单独的an-agent PR中；Loom仍独立可用用于编写/打包。
