# 接受范围和复现

[English](../../acceptance.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

初始的领域示例是现有的文件列表CLI工具包。其算法和
测试仍保留在`examples/file-list/kit/main.rs`中。没有生成的二进制文件、私有
作业目录或机器工具链配置被提交。

普通的`cargo test --locked`涵盖包/清单合约、失败或
篡改接收、秘密/私有元数据拒绝、非默认工具包绑定、
可移植发布迁移、过时证据、归档完整性以及计划绑定。
一些接收/发布测试使用显式合成程序字节且从未
执行它们；它们不适用于原生编译或领域正确性。

单独的原生macOS宿主接受需要`AN_AGENT_HOST_BIN`。运行：

```sh
AN_AGENT_HOST_BIN=/operator/selected/an-agent-host \
  cargo test --test host_handoff --locked -- --ignored --nocapture
```

正向测试遵循实际的CLI路径：scaffold -> 修改源路径绑定 -> 预览 -> 拒绝过期批准 -> 批准隔离宿主构建和域测试 -> 接收 -> 声明 -> 本地发布 -> 验证 -> 宿主检查和注册 -> 运行时预览 -> 受控执行 -> 接受文件产物。它验证无预览任务，无重复构建，输入未改变，输出完全一致，进程被回收，输出哈希值正确，且包内容中不包含私有任务和当前用户主目录路径。

负向原生测试故意使域测试失败。它检查宿主失败具体发生在测试阶段，保留了收据，并且没有产生接收程序、声明或发布。无法启动原生边界环境的环境不能算作成功认证。

这些测试被普通套件明确忽略，并被强制性 `host-handoff` CI任务明确选择。缺少宿主配置是错误。CI构建公共宿主版本 `deb3721e0429bd31f325ba3b55d8c646af1eacdf`，而不将其实现导入Loom。此固定包含独立的宿主构建调试元数据修复；该宿主更改需要其自身的审查。

将 `LOOM_ACCEPTANCE_DIR` 设置为新操作员选择的目录以保留本地证据。关闭的 `acceptance.json` 总结可以共享；完整的宿主计划、工具链配置文件、构建和审计日志仍保留在本地。CI上传仅包含该总结。总结是观察证据，而不是签名证明。

不声称有实时模型生成、第三方工作流兼容性、Linux隔离构建、整个程序安全证明或多阶段运行时。重命名源绑定仅能配置可变布局，而不是独立域。

[合格的本地总结](../../acceptance/local-run.json) 记录了使用固定宿主隐私修复的成功的macOS ARM64路径。十九个普通检查和两个明确的原生宿主测试在本地通过；格式化和clippy也通过。远程CI独立认证该PR提交。第一次、嵌套执行环境拒绝创建原生沙盒，该情况被本地记录，但未被算作成功的原生认证。

## 有限编码工具接受

历史上的 [Kimi开发工具](../examples/kimi-kit/README.md) 使用仅工具的定制代理和宿主MCP桥接。其 [可移植记录](../../acceptance/kimi-development.json) 分离了真实的K3源/工具包工作，独立审查的开发和K3-256k活动工具包取消。原生客户端磁带和机器配置文件保持私有。该工具不认证不可信的原生客户端沙盒、Linux开发或远程模型取消。无凭证的MCP权限/取消/EOF回归在协调宿主的Linux/macOS CI中运行。

新工作使用 [共享有限-MCP工具](../examples/finite-mcp/README.md) 和原生客户端配置。其独立的 [Codex记录](../../acceptance/codex-mcp.json) 认证实际开发和本地取消。提供方启动/等待/信号代码已弃用；当前工具保留准备、持久宿主结果检查和独立审查接受。历史记录保持不变。
