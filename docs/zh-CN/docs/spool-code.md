# 轮廓内容标签：丝线和套件

[English](../../spool-code.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

状态：已同意定义，修订版2。标签用于描述来源和生命周期，而非代码责任、语言、文件扩展名、目录或权威。现有合格的配置文件仍为执行限制。本修订版不实现任意运行时编辑或通用覆盖文件系统。

## 不可变基准线和可变衍生品

| 内容 | 标签 | 规则 |
| --- | --- | --- |
| 所有已选发布的文件，包括程序、配置、技能和AGENTS.md | silk | 不可变基准；通过经过审核的开发和新发布版本进行更改 |
| 一个授权的工作副本的基准程序或配置 | kit | 分离衍生品；绝不覆盖已选发布的文件 |
| 新文件、生成的程序和其他未提交的工作 | kit | 默认由开发者所有；不自动保留或可执行 |
| 已已验收的产物和已提交的状态 | 分离的 custody 记录 | 明确接受/提交并保留；绝不删除与擦除有关 |

一个位于遗留目录 `kit/` 下的文件仍然处于释放状态。其工作副本即使在字节与基准一致，包括在重置之后，也仍为 kit。重置恢复字节；它不会将可变的工作副本转变为释放状态。文件类型（程序、配置、指令、数据）与标签无关。程序并不因为实现了核心领域逻辑而变为 silk。

## 编辑与指令保护

程序和配置仅可在单独授权的工作副本中进行修改，且仅限于选定宿主配置支持的可编辑路径。基准值仍保持可用。记录拥有者实例/尝试、逻辑路径、源发布版本、基准值（如存在）以及衍生值（如存在）。新文件没有基准值。

技能指令，SKILL.md、agent.md 和 AGENTS.md 在尝试过程中受到保护。更新指令集需要经过审核的开发和新版本发布。在scratch中出现的新指令外观文件保持为惰性-kit数据：它们不能作为指令加载，不能扩大赋值范围或替换已选指令。无论其目录或文件名如何，均需保护指令资源。一个重命名的指令包，仅因其扩展名而被视作可编辑配置，是不被允许的。

Kit 是一个标签，而非权限。给文件标注 kit 不会授予编辑、执行、依赖安装、网络访问或对另一尝试的访问权限。影响入口点、依赖项、权威或宿主策略的配置更改需要重新验证/批准；包指令无法授予宿主权限。在执行前，使用合格宿主路由绑定固定选中的字节及其有效权威。不要在字节被修改时运行代码。

## 结算、重置和收集

未被保留的 kit 仅在完成整个尝试的确认后，才可进行重置或scratch收集。未知终止边界清理和自动重试。重置影响本地工作字节，而非已执行的外部效果。不暗示任何背景收集器或自动检查点继承。

保留一个有用的套件，明确作为固定字节，并作为后续工作的输入/依赖项。艺术品的 custody 不是执行权。晋升到 silk 需要审核、检查和一个新的不可变发布；更改标签不是发布操作。接受的产品和已提交的状态使用各自的保留和引用规则，并且能够存活于普通的 kit/scratch 收集中。

## 所有者和兼容性

域 `spool` 传输知识、指令、程序和业务接受含义。Loom 准备受限任务，记录受保护/可编辑路径，检查候选者并打包选定字节。宿主接受执行，实施授权，结算尝试，并拥有状态/制品/临时存储的保管权。后端提供隔离和终止证据；Shuttle 介于授权应用程序交互之间。成熟编码利用自身编辑/模型循环和原生上下文。

现有 `[silk]` / `[kit]` 字段，`silk/` / `kit/` 路径，`Kit` 别名，`file-kit-v1`，`build-kit`，`kit.*` 事件和历史 Silk 通信记录 保持其线缆和解析含义。它们是兼容绑定，而非标签定义。旧版本标识和历史凭证永不重写。

当前原生配置通过 legacy `kit/` 槽位支持固定选定文件和跨运行工作副本更新。该限制是配置限制，而非声称仅胶水可成为 kit。任意路径覆盖、添加可执行文件或配置槽位，以及运行时自我编辑，需单独获得资格宿主路由。新文件 kit 标签单独不能绕过该限制。

## 已实现的观察与下一步资格

宿主实例检查报告释放文件为 silk，现有工作副本为 kit，未注册生成工作为 kit 默认。它保留原始 `kits` 消息摘要以保持兼容性。这些观察不具权威性，不替代制品/状态记录。

Loom 任务目录标记所有基准文件为 silk；接收候选者为 kit，带有基准来源。已验证发布生成新 silk 发布。

下一步对目录独立覆盖进行明确新文件准入的资格审查：
保持指令资源不可变，将配置更改和新可执行字节绑定到新鲜批准，证明基准保留/重置，保留声明产品，并在确认收尾完成后才回收剩余 kit。重用当前宿主和 Loom 合同；不添加通用工作流程引擎或从标签推断授权。
