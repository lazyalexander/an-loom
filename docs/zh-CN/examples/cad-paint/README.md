# CAD绘画spool

[English](../../../../examples/cad-paint/README.md) · 中文译文，以英文为准。 · [中文目录](../../README.md)

CAD shuttle发出一个绑定修订的请求，包含意图、零件标识、几何体、外观观察以及操作员指令。它不拥有模型或渲染器。网络CAD宿主拥有锁。源包包括领域代理策略和一个与提供者无关的TypeScript规划器。模型端点和凭证属于其调用者。

领域代理提出保存请求中缺失的材料。工作室仅将经过验证的字符串和数字字面量转换为函数，使用一个全新的套件副本。拥有完整CAD材料后，基线可直接运行。原生交付包含Python silk和套件。在渲染过程中不需要模型连接。结果的ORA嵌入了解析后的场景、输入摘要和选定的套件摘要。在宿主中打开Krita并将一个被接受的资产交给切割器是两个独立的操作。

使用Loom dev-advance检查此目录，打包所选源代码，验证打印的存档，并使用export-native-spool-v3导出。使用与native-spool.toml匹配的绑定操作员的Python环境加载该交付。如果请求需要材料建议，请在尝试开始前将审核过的套件安装到实例中。其输入槽位是request.json。仅在单独选择的具有渲染依赖项的环境中运行接受命令。

浏览器工作室通过本地开发运行器使用相同的silk入口。其成功的渲染不会创建无代理宿主的制品接受。Loom的生产声明支持未来路由一个宿主已验收的产物。接收切割spool和订阅必须在托管宿主中分别配置。

请求中可选的 `quality` 字段选择 `final`（默认，美术通道 96 次采样）或 `preview`（8 次采样）。两者产生相同的零件图层并执行相同的像素重建检查；预览只是用美术通道的噪点换取速度。解析后的场景会记录质量，入口把各阶段耗时作为诊断信息写到 stderr。
