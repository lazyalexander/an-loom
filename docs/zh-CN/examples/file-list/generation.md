# 内部 silk 开发合同

[English](../../../../examples/file-list/generation.md) · 中文译文，以英文为准。 · [中文目录](../../README.md)

为所属的 spool 开发一个内部 silk。在适当的地方复用现有程序。不要创建虚拟机，选择执行后端，获取宿主凭证或扩大 spool 权限域代码的权限。只能通过宿主授权的接口调用外部能力。内部子进程完成并不代表整个 spool 的终止。下面的遗留路径和宿主配置文件名仍然是兼容性标记；在单独审查的迁移之前请保留它们。

如果需求发生变化，请使用现有的代码生成工具来编辑 kit/main.rs。初始的骨架是确定性的，而不是模型生成的结果。保持一个无依赖的 Rust 源代码，使用纯转换和单元测试。读取 input.txt（UTF-8，最多 8192 字节），去除空白行，去重并按字典顺序排序，然后使用 create-or-truncate 写入 output.txt。宿主提供一个全新的运行目录，并可能在 Linux 上预先创建该确切的输出文件。绝不要通过删除、重命名或创建其他文件来绕过宿主边界。不要使用网络、环境密钥、子进程或其他路径。源代码审查是不完整的证据：宿主必须强制执行执行边界。

对于不可信的源代码，请要求操作员预览并批准支持的 an-agent-host 构建工具配置文件。该隔离的构建仅限于 macOS。Linux 文件运行时支持不授权对生成代码的无限制编译。操作员可以在可信的开发环境中显式编译和测试已审查的源代码，并提供其匹配的可移植构建记录；不要伪造隔离构建的收据。在适用的构建检查之后，通过现有的 CLI 声明、打包、验证、导出和注册。
不要通过跳过测试或替换已已验收的产物来修复失败的测试。
