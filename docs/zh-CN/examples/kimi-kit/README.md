# 历史 Kimi 有限-MCP 合格性

[English](../../../../examples/kimi-kit/README.md) · 中文译文，以英文为准。 · [中文目录](../../README.md)

特定供应商的 `run`/`cancel` 驱动和自定义代理配置文件已停用。
新工作使用 [共享有限-MCP 固定装置](../finite-mcp/README.md) 与现有的原生客户端。固定装置的准备、宿主结果验证和已审核候选接受仍由原样维护；模型选择、认证、客户端启动和中断属于原生框架及其操作员。

当前的 Codex 路径已经拥有独立的真实开发和取消证据。它不添加任何替代启动器、SDK 或进程监督器。域源代码和测试仍保留在工具包中。宿主仍拥有有限授权、工具包执行、终止证据和已已验收的产物。此次停用不会移除或削弱宿主 MCP 服务。

## 现有操作员目录

使用 [最后维护的适配器和固定源版本的说明](https://github.com/lazyalexander/an-loom/tree/ff984999b7146c48cb3c8e0e15b0cba364c61af1/examples/kimi-kit) 与最初选择的二进制文件来检查一个旧的 Kimi 绑定目录。共享固定装置拒绝客户端绑定设置，而不是将其解释为新的原生客户端选择。为新工作准备一个全新的目录。不要将不确定的旧请求重新提交作为迁移步骤。

## 证据和覆盖范围

未改变的 [便携式 Kimi 接受](../../../acceptance/kimi-development.json)
记录 Kimi Code 2.3.1、K3 源/工具包工作、已审核的构建/接受和 K3-256k 活动工具包取消。它仍然是该路径的证据，而不是新客户端的合格性或远程模型终止的证明。单独的
[Cod,ex 接受](../../../acceptance/codex-mcp.json) 记录直接原生 MCP 使用。这两条记录保留其原始身份和限制。

共享结果检查仍保留在 `examples/finite-mcp/tests/`：已提交的发布、精确的未授权句柄拒绝、候选身份和构建前的拒绝。无凭证 MCP 架构、能力、重复调用、取消和传输 EOF 回归仍保留在宿主的 Linux/macOS CI 中。移除一个模型启动器会移除其客户端进程管理；它不会用提示或 CLI 退出代码替换这些测试。
