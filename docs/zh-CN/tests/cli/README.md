# CLI手off接受

[English](../../../../tests/cli/README.md) · 中文译文，以英文为准。 · [中文目录](../../README.md)

`native_state.py` 无需修改已有的原生文本参考，直接与已明确选择的实宿主进行比较。它需要Python 3标准库，合格的原生工作区后端，并且需要两个已经构建好的二进制文件。它从不以场景内的方式构建，也不调用模型。所有Python CLI案例在创建fixture或调用宿主之前，都会先咨询本地的`host_qualification.py`入口辅助程序。见[平台矩阵](../../docs/platforms.md)；辅助程序是必要条件，而不是强制检查探针或运行时权威来源。

```sh
python3 tests/cli/native_state.py --loom target/debug/an-loom \
  --host /path/to/an-agent-host --host-revision FULL_HOST_COMMIT \
  --output /private/tmp/loom-native-state-NEW
```

输出目录必须不存在。运行器检查/归档/导出源码，加载每个格式，显式种子状态，通过两次新鲜工作空间消耗固定修订号，接受输出，回收临时文件前提交状态，并在卸载后读取状态。它还暂停准入在第一次轮次后，显式恢复在第二次前，并在临时文件收集后暂停于固定检查点。恢复永远不启动下一轮。私有输入快照在状态提交前显式收集；正式产品和检查点延续仍可用。宿主测试拥有大输入和失败矩阵。参考文本转换是协议固有部分；领域状态模式/验证属于真实spool作者。

宿主拥有冲突、取消、中断和保留执行；其状态套件覆盖该矩阵。这个狭窄的loom套件仅验证包装和交接。所有收据和本地观察结果保留用于诊断。未知终止失败无重试或递归清理。`commands.local.json`包含本地路径；仅在需要时发布经过审查的可移植摘要。

`native_release.py`使用相同的前提条件和参数，使用新鲜的输出目录。它检查/归档两个实际源码修订号，导出两者原生格式，要求宿主比较其验证字节，并显式种子一个从固定检查点生成的独立实例。旧的发布/检查点保持不变。它既不授权继任者也不测试通用迁移。宿主测试拥有拒绝/失败案例。ci pins该宿主实现此命令。

`native_events.py`使用相同的前提条件和参数。它包装现有原生参考，显式v3事件接口，加载两个实例，并执行宿主拥有发布、静态订阅、批准交付、正式接受、因果消费确认和显式状态无状态输入-参考释放。固定产品和重复确认在工作/私有输入收集和参考释放后仍有效。这是显式前台交接；宿主拥有撤销/取消/故障案例。

`native_documents.py`还需`--python /selected/venv/bin/python`，并附带示例/日志报告/requirements.txt。它准备两个项目，从现有文档套件中检查/打包/导出v3，选择宿主运行时，生成接受的XLSX版本，并交付旧的精确事件以创建PPTX。原生可编辑对象和保留产品已验证。无GUI、模型、自动依赖安装或未知结果重试发生。原生-spool CI作业记录其可移植接受摘要；本地运行时配置文件和命令日志保持私密。

`native_data_state.py`使用--loom、--host、--host-revision和一个新--output目录。它打包示例/log-accumulator，通过直接/事件执行绑定固定业务和状态版本，拒绝过时提交并验证原生产品/溯源后卸载和收集。无需额外依赖、模型或GUI。宿主的对应套件拥有真实撤销和缺失证据测试；此配对套件拥有包/宿主兼容性。

原生事件CLI套件也检查宿主拥有交付库存以获取实际包的v3发布。它不实现监控或分发在loom中。

数据/state CLI烟雾测试也提交一个有限的、显式状态绑定宿主批处理以获取实际包的日志聚合器。宿主套件拥有其多入口生命周期、撤销和账本故障保证。

数据/state烟雾测试也检查宿主订阅暂停/恢复和过期批次批准以获取实际包的日志spool；loom拥有无运行时控制账本。

数据/状态烟雾也扩展到第二个相同打包版本的实例。它检查显式固定检查点播种、历史事件拒绝、新事件分发和独立旧/新状态。运行时切换仍由宿主所有。

数据/状态烟雾使用有限宿主私有材料维护进行两次运行，保留状态提交、过时冲突和下游产品断言。更大容量/并发/收集故障接受度仍由宿主所有。

数据/状态烟雾也通过宿主关闭一个旧接受的生产者版本，拒绝新版本检查出/输入选择，并保留原始接受输出库存、消耗确认、检查点和保存报告。宿主套件拥有并发接纳/取消和记录故障案例。

`registered_fanout.py`与`native_data_state.py`具有相同的参数。它打包一个生产者、一个日志聚合器和一个审计消费者。它的三个阶段覆盖一个共享固定事件、有限分发带显式状态、客户端退出后确认取消、实际监督丢失和收集。可移植摘要记录二进制身份、观察到的尝试次数和磁盘使用情况。宿主所有读者记录。
