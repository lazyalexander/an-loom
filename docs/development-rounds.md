## Round 1 contract

New native projects ship developer instructions as selected release material.
Tasks protect all selected files except explicitly editable kit paths, including
instructions, content, configuration and acceptance metadata. Changing any
selected file invalidates the development baseline. Instructions are guidance;
these reception checks do not confine an agent process or grant execution.
Existing projects need not add AGENTS.md to remain readable or packable.

Silk/kit roles describe responsibility and permitted change, not language or
quality rank. Keep authoritative rules and acceptance logic stable during kit
repairs. Explicit development tasks may evolve silk into a new validated release.
State, artifacts, configuration and documentation need their own roles; neither
silk nor kit is a catch-all classification for every selected file.

permissions, cancellation behavior and unsupported containment. Reuse the
existing adapter contracts; do not add an agent loop to Loom.

Code scanning belongs to round 3 and must not delay that handoff. Inspection
records should identify exact content, tool/rule versions, findings and unknowns.
A capability declaration is a request; the host independently authorizes it.
Use existing declaration formats rather than adding a competing YAML schema in
round 1. Packaging, execution permission and safety evidence are distinct claims.
